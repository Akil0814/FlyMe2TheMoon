# 一个物理固定步如何执行

本文说明物理世界内部一个固定步的顺序。场景先推进控制器和游戏固定步扩展，再进入物理模拟；完整场景流程见[输入架构](../input/architecture.md#一帧与一个固定步)。

## 模拟与事件顺序

1. 先检查步长有效且没有重入，再提交本步开始前的延迟命令；若已有重置请求，清空世界并结束本次物理步。
2. 获取注册参与者的快照，调用仍存活且活跃的参与者固定更新。
3. 按顺序提交延迟命令；待执行的重置优先处理。
4. 移除已销毁对象，同步活跃状态。
5. 冻结当前及上一份形状几何、地图邻接、单向规则、支撑接触和穿透对象对，再推进供插值使用的前一姿态存储。
6. 推进 Box2D 模拟。
7. 在失效标识映射仍可用时，将接触与传感器信息复制为引擎值。
8. 更新引擎接触状态，并将变换写回所属对象。
9. 使用监听器快照派发事件，再提交回调产生的物理命令。

在参与者固定更新回调中登记的新对象不属于本步参与者快照：创建提交后可以参与本步模拟，但它自身的固定更新从下一步开始。步外已注册的对象则可以参与下一次进入的物理步。没有固定步的渲染帧保留已锁存输入，等待之后消费。

## 预求解回调的边界

预求解只读取冻结快照和传入的接触流形，通过返回值决定是否接受接触。它不查询或修改原生世界，不解引用游戏对象，不派发玩法回调，也不执行命令。

位置突变应使用显式传送操作，同时重置位置与插值。物理世界重置静默清空世界；在参与者回调中请求重置时，会跳过本次尚未执行的模拟。它不会重置或停止独立 `FixedStepRuntime` 的剩余调度。异常向上传播，已经完成的模拟步不会回滚。

目标位姿、Chain 与关节创建／更新／销毁均进入同一 FIFO。目标在执行时读取当前原生姿态，固定旋转忽略目标角度；每步在模拟前解析 Motor 的第一端局部位移目标。关节创建后立即更新按队列顺序生效。Chain 先预分配子段身份，再提交原生边与映射；中途失败清理未完成资源，已完成的模拟不回滚。
