# Elysia Engine 文档维护规则

本文档规定 Elysia Engine 的文档组织、编写和维护约定，适用于新增、修改及删除项目文档的开发者。

文档应准确反映项目当前状态，帮助开发者理解引擎、使用公开接口及参与开发。

## 1. 文档分类

项目文档按照用途分为以下五类。

| 分类 | 内容 |
| --- | --- |
| 使用指南 | 构建运行、核心概念、子系统接入步骤及示例 |
| 接口与格式参考 | 公开 API、参数、返回结果、配置字段及跨组件调用契约 |
| 架构文档 | 当前引擎的模块职责、依赖关系、内部设计与运行机制 |
| 开发与贡献指南 | 编码规范、测试流程、开发约定及文档维护规则 |
| 设计文档 | 开发路线、设计提案、计划中的功能及待完成的架构迁移 |

### 使用指南

面向使用 Elysia Engine 开发游戏的开发者。

应重点说明：
- 引擎提供什么功能。
- 如何正确使用公开接口。
- 必须遵守的接口契约和生命周期约定。
- 常见错误及其处理方式。

使用指南不应依赖读者理解引擎内部实现。

### 接口与格式参考

面向已了解基本接入流程、需要查询具体调用或字段规则的开发者。

集中记录公开接口、参数、返回结果、配置结构和跨组件契约。完整字段清单只维护一份；使用指南保留操作步骤与必要示例，并链接到对应参考章节。内部调度与实现推导仍放在架构文档。

### 架构文档

面向希望了解、维护或扩展引擎的开发者。

应描述当前代码的实际设计，包括模块职责、依赖关系、关键数据结构、执行流程及设计约束。

架构文档应反映当前实现，而不是尚未落地的目标设计。

### 开发与贡献指南

面向参与引擎开发及维护的开发者。

记录项目统一的开发要求，包括代码规范、测试方式、文档维护及其他贡献约定。

### 设计文档

用于记录未来规划、设计提案及尚未完成的迁移工作。

除非明确标记为当前实现参考，否则设计文档中的类型、接口和流程均不代表已实现的功能或稳定的 API 承诺。

计划中的功能不得仅因存在设计文档，就被描述为引擎当前支持的能力。

## 2. 文档内容要求

### 准确性

文档应以当前源码、测试和实际配置为事实依据。

- 不得将计划中的功能描述为已实现。
- 不得将尚未确定的接口描述为稳定 API。
- 不得根据过时的实现推断当前行为。
- 不得声明未经验证的平台兼容性或性能表现。
- 不得省略会影响正确使用接口的重要限制。

当文档与实际实现不一致时，应检查实现和测试，确认预期行为后修正文档或代码。

### 明确适用范围

文档应根据目标读者选择合适的内容深度。

使用指南侧重调用方式和接口契约；架构文档侧重设计原因与内部运行机制。

不必在多个文档中完整重复相同内容。对于已有的详细说明，应通过链接引用。

### 接口与生命周期

涉及公开 API 时，应根据需要说明：

- 接口的用途及调用前提。
- 参数与返回值的含义。
- 对象所有权及引用的有效期。
- 错误处理与失败语义。
- 调用时机、执行顺序及其他重要限制。

尤其是涉及对象创建、场景切换、延迟销毁和资源释放的接口，不应仅依赖函数名称解释其行为。

### 代码示例

代码示例应与当前公开接口保持一致。

- 使用当前有效的类型、函数和参数。
- 明确示例所需的初始化条件。
- 避免使用已废弃或仅供内部使用的接口。
- 需要省略代码时，应确保省略部分不会造成误导。

标记为完整示例的代码应能够在声明的环境下构建和运行。

仅用于展示局部调用方式的代码片段，不要求独立编译，但应明确其必要上下文。

## 3. 文档组织与命名

### 文件组织

新文档应放入与其用途对应的目录。

- 使用说明放入使用指南。
- 当前实现说明放入架构文档。
- 开发规范放入贡献指南。
- 尚未实现的设计放入设计目录。

子系统的相关文档应尽可能集中管理，避免同一模块的说明分散在无关目录。

UI 文档按主题合并维护：使用指南首页承载完整接入教程，参考目录以八个主题页维护契约，并在首页提供任务和类名索引；架构目录首页承载内部流程。新增控件优先加入对应主题章节，不再为单个控件或共同契约新建小页。世界空间 UI、开发面板和内置设置场景保留各自指南，从 UI 入口关联。

### 文件命名

Markdown 文档统一使用 `.md` 扩展名。

建议采用小写英文及连字符命名，例如：

- `coding-standard.md`
- `build-and-run.md`
- `core-concepts.md`

目录入口使用 `README.md`。

已有文件不必仅为了统一命名而进行无意义的重命名。

教程放在 `user-guide/`，公开契约放在 `reference/`，内部机制放在 `architecture/`。指南保留完成任务所需的条件、步骤和简短示例；完整字段清单只在参考文档维护。迁移时同时修改所有入站链接、标题锚点、源码相对路径和文档示例编译配置，不保留同一正文的两份副本。
