## 删除与保留依据

审计以游戏代码、全部 60 关、Lua 剧情、角色动作池、机关组件、教程语言映射、四章星星状态、17 项成就及动态音效池为使用根；资源注册本身不视为使用证据。

删除项包括 272 张未被任何关卡引用的地形、闲置旧界面、未使用的角色首帧副本与 magicShield 动画、8 个无当前播放入口的音效，以及未注册的 latin 字体文件。动画序列中的重复帧没有去重。

持续保留机关完整的状态与组件资源族，覆盖暂停、死亡、锁定、传送、开火和爆炸等分支。检查器明确验证激光/平台/发射器等子图集，以及动态生成的 `90-1..10` 水晶音效和 `106-1..3` 结算音效。未知资源族默认保留供审查；本次没有此类遗留项。

每个删除文件的原路径、迁移路径、资源键、字节数、SHA-256 和依据，以及保留资源的引用关系，见 [机器可读整理报告](assets-cleanup-report.json)。catalog 中的原作尺寸元数据不作无关删改。

## 验证

资源与引擎/存档基线共核对 1,728 个保留文件，内容哈希全部一致。纹理、音频和动画清单的保留项除路径外保持相同，包括动画帧数、帧顺序、速度和循环设置。基线工作区没有预先存在的未提交改动。

验证结果与原始日志见 [本次验证目录](test-evidence/assets-cleanup/validation.json)。大体积截图和独立临时运行目录的位置保存在 `out/qa/assets-cleanup`。

原始第 39 关暂停回放在 7.5 秒截止时，清理前后都未达到累计运行 0.5 秒的断言。保留两次失败，并用相同输入、相同断言、8.5 秒截止时间补充验证，两版均通过；没有修改原场景脚本或游戏规则。

## 后续使用

```bat
python game/tools/asset_usage.py --check-hd --report out/qa/assets-audit.json
```

检查会验证动态资源、清单文件、动画帧、字体、本地化、高清来源和遗留路径。默认检查不删除文件；`--prune` 只按同一审计策略移除确认闲置项。

完整内容、界面和音频导入器共用该策略，不会重新留下被清理的资源。导入器保留已登记的定制制作名单图片。验证导入时设置 `FLY_ASSETS_ROOT` 指向完整临时资源副本，设置 `FLY_IMPORT_REPORT_ROOT` 重定向报告；本次已在临时副本运行内容、装饰、界面、音频导入，并再次通过资源及高清检查。

独立输入回放检查工具：

```bat
python game/tools/verify_asset_cleanup.py --build x64-Debug --label my-check
```

它将 EXE、SDL3.dll 和资源复制到项目之外的临时目录，运行已有场景，证据写入 `out/qa/assets-cleanup/my-check`；不使用玩家存档。`--scenarios` 可选择其他现有场景，临时目录保留供检查。
