# 008：提供二维贴图粒子系统与运行时发射器

日期：2026-10-25。

状态：待引擎评估与实现。用户已决定等待引擎粒子功能，角色脚部飞行尾焰暂缓接入；本请求不包含引擎实现或新的游戏层粒子实现。

目标：通过公开接口创建二维贴图粒子、更新发射参数并管理其生命周期，使 FlyMe2TheMoon 能恢复原作脚部尾焰，并逐步复用到激光命中星点、风场叶片等现有表现。

## 1. 当前缺失与游戏需求

当前引擎的 `docs/engine/design/roadmap.md` 将粒子系统列为计划中的能力。已检查以下公开接口与实现：

| 现有能力 | 可复用部分 | 尚不能覆盖的需求 |
|---|---|---|
| `RenderCommand`、世界坐标投影与 SDL 执行器 | 贴图、源矩形、位置、旋转、尺寸、透明度、RGB 调制、相机投影 | 不管理粒子的生成、运动、寿命、容量或发射器；命令没有显式混合模式字段 |
| `ResourceService`、纹理与图集 | 资源注册、加载与共享 | 粒子实例与资源的生命周期约定尚未提供 |
| `Animation`、`AnimationEffect` | 逐帧动画及播放生命周期 | 不能直接表达大量具有独立寿命和运动状态的连续粒子 |
| `EffectService`、屏幕特效及飘字 | 特效入口、活动场景归属与部分句柄管理经验 | 尚无粒子定义、发射器创建、持续控制和状态查询接口 |
| Scene / GameObject 更新与销毁 | 更新、暂停、安全修改阶段和场景退出清理 | 需要明确粒子如何接入这些既有生命周期 |

游戏已有 `game/gameplay/laser_visual.h` 和 `wind_visual.h`，自行维护少量星点、叶片并提交绘制命令。这证明基础渲染能力可用，但多个效果继续各自维护发射、随机、回收和暂停策略会增加重复逻辑。角色尾焰属于持续发射且实时受推力控制的效果，适合由引擎提供通用运行时，游戏保留原作参数与状态映射。

## 2. 原作证据与首个接入目标

只静态读取本地参考程序，不执行原程序。相关方法：

- `RoleView.createParticle`，地址 `0xcf59c`：创建 `CCParticleSystemQuad`，设置容量、寿命、发射、尺寸、运动、颜色与纹理。
- `RoleView.updateParticleByPushForce:fireAngleDegrees:`，地址 `0xd0258`：根据推力实时更新发射角、起始尺寸和结束尺寸。
- `RoleView.load:`，地址 `0xcfcf0`，及 `updateStateByPush:`，地址 `0xd06b4`：挂接到角色显示层并控制可见状态。
- 汇编摘录保存在本地 `out/qa/role-flight-particles/`；上述方法名和地址可用于重新核验，临时输出不作为唯一依据。

| 已核实项目 | 原作值/行为 | 对引擎的要求 |
|---|---|---|
| 纹理 | 单张 `fire.png` | 支持独立纹理粒子，不能要求提供动画序列 |
| 容量 | 60 粒 | 固定或有上限的粒子池 |
| 发射持续时间 | -1，持续发射 | 支持无限持续、由游戏显式停止 |
| 寿命 | 0.2 秒，随机偏差 0.02 秒 | 每粒独立寿命及出生时随机采样 |
| 发射率 | 60 / 0.2，即 300 粒/秒 | 按时间累计发射，支持非整数余量 |
| 初始发射角与偏差 | Y-up 下 270°、偏差 9° | 方向和角度随机范围；游戏接入时转换坐标约定 |
| 初速度 | 250，随机偏差 25 | 速度与出生时随机偏差 |
| 重力 | Y-up 下 (0,-100) | 二维加速度；游戏接入时转换为 Y-down |
| 推力驱动尺寸 | 起始尺寸 clamp(force,2,32)，结束尺寸 clamp(force×0.5,1,16) | 运行中修改后续新粒子的尺寸参数，无需重建发射器 |
| 颜色与显示 | 有独立颜色设置及角色状态显隐 | RGBA、颜色过渡、独立显示控制 |

表中为原方法设置值。纹理缩放后的最终屏幕尺寸、完整颜色变化、粒子坐标模式、混合方式及角色不同状态下的精确衔接仍需游戏接入时校准，不将其预先标为完全还原。尤其不能因效果发光就认定原作必定使用 Additive。

## 3. 首版需要提供的功能

### 3.1 粒子定义、发射与回收

- 可描述贴图/图集帧、最大粒子数、寿命及偏差、发射率、发射持续时间、出生位置及偏差、发射角及偏差、初速度及偏差、二维加速度。
- 支持持续发射和一次性指定数量的 burst，覆盖尾焰、火花及短暂爆散。首版无需复杂形状发射器，点发射与矩形位置偏差即可。
- 容量达到上限时不得继续分配；建议丢弃本次超额生成，避免恢复容量后集中补发。明确大 delta 的子步、步数或发射预算策略，避免补发风暴和无界计算。
- 粒子过期自动回收；正常更新不应为每粒创建 GameObject、PhysicsBody 或独立资源实例。
- 支持显式随机种子，使测试和回放可重复；默认实例之间不必产生相同随机序列。

### 3.2 尺寸、颜色与运行中调参

- 支持起始/结束尺寸、RGBA 和旋转角，并按归一化寿命插值；支持尺寸、颜色、旋转的出生随机偏差。首版线性插值即可。
- 运行中可修改发射率、方向、速度、尺寸、颜色和位置等参数，角色每帧更新这些值无需销毁重建发射器。
- 明确参数修改的作用范围：建议默认只影响后续出生的粒子；存量粒子的出生参数保持不变。若提供整体变更能力，应使用独立操作并说明语义。
- 宽高比例和旋转锚点可控；同一纹理可被多个发射器共享，不应复制纹理或污染其他实例的颜色/透明度。

### 3.3 坐标空间与附着变换

- 支持世界空间与发射器局部空间两种模式。世界空间中，粒子出生后保留世界轨迹；局部空间中，存量粒子随发射器变换。
- 发射器支持位置、旋转、缩放和局部偏移，以便挂在角色脚部或移动/旋转机关上。变换可由游戏每帧显式提供，无需首版实现新的父子对象体系。
- 文档明确角度单位与正方向、EU/秒等单位，以及位置偏差、速度、加速度、尺寸分别在哪个空间采样/积分，如何应用非均匀缩放，避免重复旋转和缩放。
- 传送或重试时允许游戏选择清空或保留存量粒子，不由系统猜测游戏事件。

### 3.4 生命周期、暂停与状态查询

必须区分下列操作，具体名称由引擎确定：

| 操作 | 所需语义 |
|---|---|
| 开始/恢复发射 | 允许产生新粒子；明确是否重置持续时间；从停止状态恢复时不补发停止期间的粒子 |
| 停止发射 | 不再产生新粒子，已有粒子继续运动并自然消失 |
| 清空/重置 | 立即清空存量，重置时间与发射余量；明确是否同时恢复发射及重置随机序列 |
| 暂停/恢复模拟 | 冻结/恢复发射计时、粒子年龄和运动；暂停期间不积累补发时间 |
| 显示/隐藏 | 只影响绘制；与停止发射、暂停模拟分开定义 |
| 销毁 | 立即释放实例，后续句柄失效，解绑所有回调与宿主关联 |

提供 emitting、paused、alive_count、finished/empty 等只读状态。持续发射且暂时为空不能误判为完成；停止或有限发射结束后，存量清空才能完成。若支持完成回调，须明确触发时机、是否仅一次，以及取消/场景退出时是否触发。

默认服从所属场景暂停；若支持暂停时继续播放，使用现有更新策略或显式选项。出生、到达终点、传送和死亡时如何控制尾焰由游戏决定，原作的可见状态不应直接固化进引擎。

### 3.5 渲染、混合与资源安全

- 经现有渲染管线提交，正确应用相机、缩放、层级和可见状态，能绘制在角色指定前后层。
- 提供明确的 Alpha 与 Additive 混合选择。Additive 是其他发光粒子的通用需求，不是已经证明的原脚部尾焰配置；预乘 Alpha 的支持方式和纹理要求需明确，避免黑边或过亮。
- 混合、RGBA 调制必须作用于本次绘制，正常路径和绘制失败路径均恢复共享纹理/渲染状态。游戏不需要自行调用 SDL 改全局或共享纹理状态。
- 粒子实例借用已有资源管理服务的纹理或帧。明确资源存活约束、场景销毁顺序，以及资源缺失、卸载或重载时的行为，不能留下悬空纹理指针。
- 首版 CPU 更新和现有贴图提交即可；不要求 GPU 粒子、Shader、粒子碰撞、编辑器、Cocos 对象兼容或 `.plist` 导入。

## 4. 建议的 API 与责任边界

以下是接口职责建议，不表示当前已有这些 API，也不限定最终类型名。

建议提供不可变的粒子效果定义，以及各实例独立的发射器状态。创建请求包含定义/资源引用、初始变换、随机种子、场景归属和暂停策略；返回可安全操作的实例或句柄。

可结合现有 `EffectService` 和场景特效管理实现，也可先交付场景拥有的粒子对象。两种方式任选一种完整公开路径即可，不要求同时维护两个系统。若采用服务句柄，须支持参数更新、变换更新、发射/暂停/清空/取消及状态查询；若采用场景对象，须提供等价能力并遵守现有对象修改阶段。

- **引擎负责**：通用粒子采样、发射与容量控制、积分、生命周期、场景归属、渲染状态、资源约束、无效参数与失效句柄处理。
- **游戏负责**：原贴图导入和资源键、原参数、推力到粒子参数的映射、角色脚部偏移、进入/传送/死亡等状态控制及视觉校准。
- 创建或参数更新失败应返回可检查结果和诊断；验证 NaN/Inf、非正寿命、非法容量、负发射率及随机范围等。运行时无效更新不应让实例进入半更新状态；失效句柄不得误操作后来创建的实例。
- 场景退出、重入和重试时由所属场景清理实例，不依赖长期保存宿主裸指针。创建/销毁/完成回调与现有安全修改阶段兼容。

JSON 定义、清单加载、可视化调试和性能统计可后续增加；首版提供类型化配置、状态查询与一个可运行示例即能接入本游戏。

## 5. 验收条件

以下为请求的验收项，当前尚未执行，也不表示功能已经实现。

1. **基础与容量**：60 粒容量、300 粒/秒、寿命 0.2±0.02 的连续发射稳定运行；容量不超限；burst、发射余量和随机种子有可重复测试。
2. **时间推进**：相同固定种子、相同更新序列得到相同结果；30/60/120 Hz 下发射数量及生命周期在明确的采样误差内一致；暂停、大 delta 和重新恢复不产生积压补发或无限循环。无需承诺不同步长逐粒完全一致。
3. **运动与空间**：位置、速度、加速度、尺寸和颜色插值有数值测试；移动、旋转、缩放发射器时，世界/局部空间分别符合约定；相机变化只影响投影。
4. **实时调参**：连续修改方向、发射率和尺寸后，新粒子使用新值，存量粒子保持约定语义；无需重复加载贴图或重建实例。
5. **状态与清理**：停止发射可自然收尾，清空可立即移除，隐藏与暂停语义独立；场景退出、切换、重试和回调中取消都安全；旧句柄不影响新实例，完成回调不重复执行。
6. **渲染隔离**：两个发射器共享纹理但使用不同颜色、透明度和混合模式，再绘制普通精灵，显示互不污染；覆盖绘制失败后的状态恢复。透明边缘和混合结果须查看实际截图。
7. **资源和输入错误**：资源缺失、无效参数、资源生命周期错误有可定位诊断；验证失败不会留下半注册实例或泄漏。
8. **性能边界**：对 60 粒尾焰和项目预期并存实例给出实测活动粒子数、分配情况与运行表现。容量有上限，首版无需预先承诺大规模 GPU 性能。
9. **示例与文档**：演示按输入改变尾焰方向/大小、停止并收尾、暂停/恢复、清空重启、世界/局部空间和混合选择；说明单位、所有权、资源约束、返回失败和回调时机。

## 6. 游戏接入计划与替代方案

收到引擎更新与回执后，先核对实际交付接口和测试证据，再导入 `fire.png`、按原参数配置发射器，并连接角色推力、脚部位置和状态切换。游戏侧验证键盘/鼠标推力变化、开场运镜、暂停、死亡重试、月亮过渡和传送，确认不出现残留尾焰、跨场景粒子或停顿后的集中补发。

现有激光星点和风场叶片可继续使用当前游戏实现，不作为首版接入的前置迁移任务。通用能力稳定后，再按收益迁移其共享的发射与运动部分，保留各效果独立的原作参数和特殊表现。

可行替代方案是复用 `LaserVisual` 中的有限粒子更新与绘制逻辑，新增游戏专用尾焰类；该方案技术上可行，但用户已选择等待引擎更新，本轮不实施。此次缺失只阻塞脚部尾焰的完整呈现，不阻塞飞行、碰撞、追踪孢子或其他已有玩法。

请求完成标准：引擎交付可公开使用的粒子运行时、必要渲染支持、测试和示例，并有回执说明实际支持项与限制。引擎功能交付与本游戏视觉还原验收分别记录，不能相互替代。
